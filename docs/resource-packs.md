# 轻量客户端和资源包

轻量客户端保留游戏规则和交互，默认以文字、色块及系统字体游玩。美术和语音按资源包下载到本机，后续启动复用。资源服务可以公开访问，网页和大厅继续使用各自现有的认证。

## 构建与部署

执行 `pnpm build`，生成以下产物。

| 路径                    | 内容                                                 |
| ----------------------- | ---------------------------------------------------- |
| `dist`                  | 默认轻量运行目录，供网页、Electron 和 Capacitor 打包 |
| `output/resource-packs` | 可公开托管的加密分卷和资源清单                       |
| `output/runtime-full`   | 包含全部约定素材的离线运行目录                       |
| `output/mobile-runtime` | 移动端同步时生成的独立目录，包含 Capacitor preload   |

执行 `pnpm build:full` 可让 `dist` 保留完整素材。正式 Release 的 `noname.core.zip` 使用轻量 `dist`，`noname.full.zip` 使用完整离线目录。Windows、Android 和 iOS 的常规构建默认接收轻量 `dist`。

移动端同步先复制 `dist`，再在独立目录生成 preload，避免 Android 或 iOS 的启动脚本混入网页和 Electron 包。

发布前设置 `NONAME_RESOURCE_BASE_URL`，指向资源服务的目录地址。将 `output/resource-packs/*.nrp` 上传到该地址，保持文件名不变。文件名包含密钥版本和明文 ZIP 的内容哈希，可以长期保存。没有设置时，清单使用当前分支版本的 GitHub Release 附件地址，下载渠道须支持客户端使用的公开 GET 请求和跨域访问。浏览器不能使用不允许 CORS 的下载地址。

正式资源采用 OSS 直接下载，完整步骤见 [OSS 资源发布](./oss-resources.md)。可设置 `NONAME_RESOURCE_ROOT_URL`，由构建自动追加 `v<当前发行版本>/`，避免每次升级手动修改完整目录。显式的 `NONAME_RESOURCE_BASE_URL` 优先。各平台 GitHub 工作流读取同名仓库变量；未设置任何资源地址时仍使用上述 GitHub 默认源。

资源服务应允许 `Access-Control-Allow-Origin: *`，正确返回加密分卷并支持 HTTPS。跨域下载不携带网页的认证信息。素材请求和分卷下载不需要经由游戏服务器转发。已有资源分卷不覆盖，内容变化或密钥轮换会生成新文件名。

发布仓库与实际下载站可以分开配置。`NONAME_RESOURCE_BASE_URL` 保留版本仓库入口，`NONAME_RESOURCE_DELIVERY_URL` 指向支持 CORS 的 OSS、COS 或 CDN 目录。客户端默认使用分发地址，手动设置的下载地址优先。两个目录使用相同的分卷文件名和密文内容，解密规则不变。地址改变会更新核心构建标识，让浏览器刷新清单；已经缓存的素材仍按明文哈希复用。

网页部署只需上传 `dist`。使用 HTTPS 或 localhost，以启用持久缓存和资源 Worker。保留 `resource-worker.js`、`resource-manifest.json`、`resource-version.json` 和 `noname/resources` 的相对位置。网页可以使用静态托管，核心文件读取和目录发现从构建清单获得；文件写入仍遵循原文件服务权限，资源下载不会写入服务器。

使用 HTTP Basic 认证时，浏览器注册模块 Worker 的请求可能不携带页面凭据。将 `resource-worker.js`、`noname/resources/worker.js` 和 `noname/resources/manifest.js` 三个无密钥引导脚本允许匿名读取。页面、`resource-manifest.json`、`resource-key.json` 和文件接口继续使用原认证。不要放开整个资源模块目录。

每次打开网页先检查很小的 `resource-version.json`。构建标识变化时才刷新清单并切换核心缓存，避免长期命中旧代码。素材按自身哈希保存，核心更新不会让未变化的素材重新下载。

浏览器启动按下载状态逐项核对缓存，每批最多 32 项，并移除失效记录。启动不调用 `Cache.keys()` 获取全部资源请求，避免全量下载后超过浏览器单次缓存枚举限制。核验保留已有素材，缺少的卡牌资源会回退到文字模式。

旧启动缓存阻止网页加载修复版本时，在同一浏览器打开站点的 `resource-recovery.html`，点击“更新启动文件并重新打开”。恢复页只注销当前站点作用域的 Worker，删除 `noname-core-<构建标识>` 核心缓存，保留素材缓存和 IndexedDB 设置。该页不纳入核心缓存；HTTP Basic 部署应单独允许它匿名读取，页面不包含游戏数据或解密配置。

## 下载并使用资源

1. 打开右上角的“资源”。
2. 点击“全部下载”，或按需下载卡牌图片、武将立绘、语音、字体或扩展美术。
3. 查看总文件进度和当前分卷进度。点击“暂停下载”可停止，再次点击下载会检查并跳过已保存内容。正在传输的未完成分卷会重新下载。
4. 勾选使用已下载美术的选项，下一次启动生效。

卡牌图片尚未就绪时继续使用文字模式，避免空白牌面。没有下载完整美术的集成扩展暂不加载。皮肤切换还需要千幻聆音的美术就绪。缺少素材不阻止文字模式开局。下载失败会保留已完成的内容，并显示重试入口。临时切回文字模式不删除已下载资源。

## 核心与素材边界

核心保留脚本、CSS、Worker、配置 JSON、运行时库、规则包、许可证和类型声明。图片、音频、视频、字体、Spine atlas 与骨骼数据进入素材包，路径保持不变。分卷通常按 24 MiB 未压缩大小切分，单个大文件不拆断。ZIP 中不接受清单以外的文件，也不允许通过素材包覆盖可执行脚本。

`resource-manifest.json` 使用 schema 2，记录核心文件路径、各素材的字节数和 SHA-256、资源包归属、分卷文件清单、密文长度及明文 ZIP 的 SHA-256。下载器检查密文长度，完成 AES-GCM 认证解密，再检查 ZIP 和每个文件的哈希，成功后才写入存储。已保存且哈希匹配的文件不重复写入，完整保存的分卷不会再次下载。

分卷 ZIP 的 DOS 日期固定为 `2000-01-01 00:00:00`，不随构建机器时区变化。清单中的 `archiveVersion: 1` 标记此规则；构建器不复用缺少该标记的旧分卷缓存，避免旧 ZIP 元数据继续造成文件名差异。跨时区回归测试覆盖 UTC、上海和洛杉矶。

## 资源加密与密钥

每个 ZIP 分卷使用 AES-256-GCM 加密。`.nrp` 格式由 `NRP2` 标识、12 字节随机 IV、密文和 16 字节认证标签组成。认证附加数据绑定格式版本、密钥标识及明文 ZIP 哈希。每次加密使用新的随机 IV；同一内容和密钥生成的分卷名称相同，不同构建生成的密文均可由同一客户端验证和解密。

本地构建默认生成并复用 `.audit/resource-packs.key`，不纳入 Git。也可通过 `NONAME_RESOURCE_KEY_FILE` 指定 32 字节密钥文件，或通过 `NONAME_RESOURCE_KEY` 提供其 Base64 编码。正式 CI 构建必须配置相同的 `NONAME_RESOURCE_KEY` secret，确保各平台使用同一密钥版本。

构建将 `resource-key.json` 放在客户端核心目录，公开资源目录只有密文分卷及不含密钥的清单。不要将 `resource-key.json` 或原始密钥上传到资源仓库。网页通过与核心代码相同的认证读取解密配置，原生客户端随包携带。完整离线目录也属于客户端产物，包含明文素材。

这层加密防止直接解压和预览 CNB 附件。能够取得客户端的人仍可提取密钥或复制解密后的缓存，不构成 DRM。密钥轮换不使已泄露的旧资源重新保密。

文字模式保留卡名、武将名、花色、点数和交互控件。背面牌继续隐藏其内容，国战暗将继续沿用原来的隐藏状态。文字模式跳过集成扩展，不改变核心卡牌、武将及模式规则。

## 各端保存位置

| 平台     | 保存与读取                                                                             |
| -------- | -------------------------------------------------------------------------------------- |
| 浏览器   | Cache Storage 保存按哈希索引的素材；资源 Worker 以原 URL 返回缓存，包括音频 Range 请求 |
| Electron | `userData/Resources`，本地协议优先读取此目录；资源文件 API 使用同一份清单              |
| Android  | 复用现有 SAF 或 app 私有可写覆盖目录                                                   |
| iOS      | 复用 Documents 覆盖目录，静态资源请求由现有 `NonameRouter` 读取                        |

浏览器可能回收站点存储。下载器请求持久存储权限，并在再次下载时检查文件是否仍存在。下载清单和外观设置保存在独立 IndexedDB 中，避免大清单触及 localStorage 容量上限。原生文件写入后读回校验，桌面端使用临时文件再替换正式文件。用户清理浏览器数据、清除 app 数据或卸载应用后，需要重新获取相应资源。下载完成标记不替代实际文件检查。

桌面和原生端启动时检查已记录文件是否存在，桌面端同时检查大小。缺少卡牌素材时自动回到文字模式。完整哈希检查在点击“下载 / 检查”时执行，避免每次启动读取全部资源。

## 验证

运行 `pnpm test:distribution`，检查轻量包保留规则与 Worker、分卷还原、缓存复用、校验失败、目录越界及缓存音频 Range 响应。移动端启动适配器另运行 `pnpm -F @noname/mobile test:android-startup`。

Android 仪器测试由 `node scripts/verify-resource-android.mjs --device emulator-N --adb <adb路径>` 顺序驱动，每个阶段之间强制停止进程。先构建 release APK 和对应的 AndroidTest APK。驱动仅接受可丢弃的模拟器，会清空其中的游戏测试数据，验证文字对局、加密资源保存、进程重启复用及缺图回退。

构建、源码测试、浏览器运行和真实移动设备是不同验证范围。原生覆盖目录沿用已有实现，但新下载流程仍需在 Android 和 iOS 真机验证。Windows 环境不能生成或验证已签名 iOS 安装包。
