# 使用密钥限制大厅访问

在项目根目录安装依赖，然后启动独立大厅服务。

```sh
pnpm install
LOBBY_PASSWORD='替换为你的大厅密钥' pnpm -F @noname/server dev
```

PowerShell 使用下面的写法。

```powershell
$env:LOBBY_PASSWORD = '替换为你的大厅密钥'
pnpm -F @noname/server dev
```

在客户端的联机连接页填写服务器地址和“大厅密钥”，然后点击“连接”。地址示例为 `服务器IP:8082`。通过 TLS 反向代理访问时填写 `wss://你的域名`。

认证通过之前，服务器只发送认证要求，不发送大厅列表。错误、缺失的密钥和认证前的大厅操作都会导致连接关闭。未提交认证的连接会在 10 秒后关闭。

认证成功的密钥按完整服务器地址保存在当前客户端的 `localStorage` 中。重新打开客户端后，点击“最近连接”中的大厅即可使用已保存的密钥。服务端仍会校验密钥。密钥不会写入游戏配置、最近连接列表或邀请链接。认证失败会清除此地址的缓存，随后可以重新填写。清除“最近连接”时也会删除已保存的大厅密钥。

客户端不允许持久存储时，密钥仍可在当前页面会话中使用。Android 客户端支持直接填写 `服务器IP:端口` 连接 WS 大厅，也支持填写完整的 WSS 地址。

同一大厅的玩家使用同一个密钥。它用于大厅准入，不替代原有 `onlineKey`，也不能区分具体玩家或单独撤销某个玩家的访问权。公网部署请使用 WSS，普通 WS 不加密密钥和游戏消息。

未设置 `LOBBY_PASSWORD` 时，服务保持公开，旧客户端可继续连接。显式设置为空字符串会启动报错。开启密钥认证的大厅需要使用支持密钥输入的新客户端。

这项配置仅作用于 `@noname/server` 独立大厅。游戏界面内“启动服务器”的直连房间不使用此配置。

修改密钥后重启服务。所有连接会断开，使用旧缓存的客户端需要重新填写密钥。

运行协议测试。

```sh
pnpm -F @noname/server test
```
