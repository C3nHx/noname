# 客户端诊断记录

客户端自动记录资源加载失败和游戏异常。部署了诊断服务的 Web 版本会分批上报到当前游戏站点，由服务器保存，不需要玩家手动导出。网络不可用时仍保留本机记录并重试。旧版本在功能启用前没有记录的错误无法补录。

## 在 Web 端使用

联网刷新页面后，新的错误会自动上报。右上角“资源”面板显示上报状态和当前会话编号。再次遇到异常时，提供大致发生时间；维护者可以直接检索服务器记录，也可用会话编号定位，无需从手机或浏览器导出文件。

上传失败不会弹窗或中断游戏，客户端会逐步延长重试间隔，最长约五分钟。已确认的记录保留在本机但不重复上传；错误次数增加时会发送新版本。服务器或页面在确认前中断，重传可能重复写入相同版本，管理检索按记录 ID 和次数合并，不重复计数。

自动上报只由 Web 部署入口启用，并限定到当前站点。接收接口沿用网页认证，额外检查同源 Origin、JSON 格式、请求大小和速率。服务器不会通过公开文件或游戏文件 API 提供其他玩家的日志。

## 本机导出备用

联网刷新网页以获得新客户端。再次遇到异常时，从右上角“资源”面板点击“导出诊断记录”，或打开“选项 → 其它 → 导出诊断记录”。导出的是可读 JSON 文件，可以交给维护者排查。

游戏启动失败、无法打开菜单时，可在同一浏览器打开站点的 `resource-recovery.html`，直接点击“导出诊断记录”。该入口读取既有本机记录，不需要重置游戏或清理素材。

浏览器和 Electron 使用现有文件下载能力。Capacitor 客户端使用现有导出路径，写入游戏目录的 `export` 子目录。已安装的旧 APK 不会因网页部署自动获得新功能，需要包含诊断功能的新客户端。

“选项 → 其它 → 清空本机诊断记录”只删除本机诊断数据库，不删除存档、设置或素材缓存，也不删除已经保存在服务器的记录。

## 记录内容

每条记录包含类型、来源、第一次及最近一次时间、重复次数、错误消息、调用栈、失败路径和已知 HTTP 状态。上下文包含版本、构建提交、平台、游戏模式、启用扩展、当前事件名称及步骤、技能与卡牌名称，不保存完整事件对象或手牌。

记录覆盖：

- 页面脚本异常与未处理的 Promise rejection。
- 启动失败、被现有逻辑忽略的事件异常、扩展和武将包加载失败。
- 图片、脚本、样式与音频元素的加载失败，以及既有 XHR 接口的 HTTP、网络和 JSON 解析错误。
- 资源 Worker 读不到已标记下载的素材，包括原来只返回透明占位图的缓存缺失；真实素材 HTTP 请求失败。

同一会话的相同错误合并计数，最多保留最近 200 条、约 256 KiB 的记录。IndexedDB 与游戏存档、素材状态使用不同数据库。多个页面各自收集，通过数据库事务合并保存。存储不可用时仍保留当前页面的内存记录，导出中的 `persistence` 会显示 `memory`；这些内存记录无法在关闭页面后恢复。强制结束进程前尚未提交的异步记录也可能丢失。

文字模式中有意未下载的素材不会因为透明占位图而报告缓存丢失。浏览器正常回退所用的 `preload.js` 探测不作为素材 HTTP 故障。资源失败不增加弹窗、不暂停游戏，也不会自动删除或重下资源。

URL 去除账号、密码、查询参数及片段。记录不主动采集请求头、响应正文、Cookie、完整配置或资源解密材料；已知凭据字段也从上下文中移除。上报和导出仍包含设备、版本、扩展与游戏事件信息。

## 服务端保存与检索

文件服务仅在设置 `NONAME_CLIENT_DIAGNOSTICS_DIR` 与 `NONAME_CLIENT_DIAGNOSTICS_ORIGIN` 后启用接收。前者必须位于公开网页目录之外，后者是带协议和可选端口、没有路径的站点 Origin。生产后端应只监听回环地址，由现有认证反向代理提供访问；Origin 检查用于防跨站写入，不代替身份认证。

日志按 NDJSON 保存，默认每卷 5 MiB、共四卷，约 20 MiB，容量达到后轮换。目录与文件分别设为 `0700`、`0600`。日志目录独立于版本发布目录，更新或重启服务不会清空。保留时长取决于实际错误数量，不承诺固定天数。

每批最多 20 条、128 KiB，服务端每分钟最多接受 120 次请求。客户端使用更小的批量并在失败后重试。服务端只返回接收确认；读取完整日志需要服务器管理权限，可运行随 Web 包提供的脚本：

```sh
node server/read-client-diagnostics.mjs --directory /path/to/private-logs --since '2026-11-10T12:00:00+08:00' --limit 200
node server/read-client-diagnostics.mjs --directory /path/to/private-logs --session '<会话编号>'
```

脚本只读固定的日志卷，按记录 ID 合并重传和计数更新，输出 JSON。既有文件接口的只读限制保持不变。

## 使用记录修复

维护者先按类型、失败路径、状态码及重复次数筛选，结合构建标识、扩展和当前事件复现。`cache-miss` 表示下载状态与实际缓存不一致；`http-error` 需要区分引用路径错误、未打包素材和原作者本就缺少的可选文件。逻辑异常优先查看调用栈及事件、技能信息。

诊断记录提供排查证据，不会自动改动游戏规则。每次修复仍需复现并验证原问题，再检查对应记录不再出现。
