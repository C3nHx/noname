# Web 资源分发遗留

截至 2026-11-09，CNB 保留为加密资源发布仓库，Web 实际下载方式尚未选择。本次按用户要求收尾，将分发选择与最新轻量 Web 的阿里云部署留待后续处理。

## 已完成的基础

- 轻量客户端先以文字模式游玩，资源包下载、认证解密后保存到本机，后续启动复用。
- 天庭、奇妙工具及其专属资源已移除。
- 资源采用 AES-256-GCM 加密，源码和公开资源仓库不保存实际密钥。客户端携带解密材料，这层加密不能阻止取得客户端的人提取资源。
- `C3nHx/noname` 已配置 Actions secret `NONAME_RESOURCE_KEY`，各平台正式构建可以复用同一资源密钥。
- 下载配置已分开。`NONAME_RESOURCE_BASE_URL` 指向 CNB 版本仓库，`NONAME_RESOURCE_DELIVERY_URL` 可指向独立下载目录。

运行时代码已推送到 `fork`，最近的实现提交为 `17504184`，对应分支版本 `1.11.7-c3nhx.3`。本轮收尾文档和 skill 在后续提交中保存。

## 保留的三个方案

| 方案                      | 实施内容                                                                                                | 使用体验                                     | 成本与限制                                                     |
| ------------------------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------- | -------------------------------------------------------------- |
| 独立 OSS、COS 或 CDN 分发 | 将 CNB 中同一批密文分卷和公开清单复制到支持 HTTPS、CORS 的版本目录，配置 `NONAME_RESOURCE_DELIVERY_URL` | 网页内按需下载并缓存，资源流量不经游戏服务器 | 需要对象存储或 CDN 及其存储、请求和出网费用，尚未创建或配置    |
| 阿里云服务端转发          | 游戏站点的服务端读取 CNB，向浏览器流式返回密文，限定允许的版本和文件                                    | 可在网页内自动下载，CNB 继续保存源文件       | 资源流量仍经过现有服务器出口，不能解决原有小带宽瓶颈；尚未实现 |
| CNB 手动下载后导入        | 浏览器跳转下载 `.nrp`，客户端提供本地导入、解密、校验和缓存入口                                         | 首次多一步手动操作，导入后可复用缓存         | 不需要另建下载服务，但本地资源包导入功能尚未实现               |

第一种最符合聚会时快速启动和后续推广的目标。它的落地步骤是选择 Bucket 与区域、上传加密资源、配置公开读取与 CORS、验证真实浏览器下载，再构建部署轻量 Web。自定义资源域和 CDN 可按需要增加。创建付费服务仍需用户决定，询问实现方式不代表授权购买。

仅返回 CNB 重定向地址不列为第四种方案。最终文件域同样拒绝外站 Origin，这条路径已实测失败。

## 恢复工作

1. 按 [上游与资源发布 skill](../.agents/skills/noname-upstream-release/SKILL.md) 核对源码、版本、密钥和当前发布收据。
2. 选择上述一种分发方式。若选择对象存储，确认 Bucket、区域、访问地址和可用的上传权限，通过安全凭证入口提供访问材料。
3. 实现并验证实际下载路径。独立分发时复用 CNB 中已发布的密文，保留文件名；不要将 `resource-key.json` 或原始密钥复制到资源服务。
4. 确定版本目录与核心配置后重新构建并验证。继续未完成的 `.3` 发布时核对原分卷收据；若期间已有最终客户端或清单发布，则使用新修订号，避免覆盖。
5. 使用 `--catalog-only` 发布并回读最终 CNB 清单。该阶段不重复下载全部分卷；若远端附件有变动或状态存疑，先重跑 `--parts-only` 验证。收据变成 `complete` 后再将 CNB 发布标为完成。
6. 打包并部署最新轻量 Web，保留回滚版本。验证网页认证、只读文件边界、大厅连接、真实资源下载、进程重启复用和离线缓存。

当前没有配置多源自动切换，也没有将 CNB 发布或对象存储同步接入 GitHub Actions。现有构建与发布脚本的用法见 [CNB 发布说明](./cnb-resources.md) 和 [资源包说明](./resource-packs.md)。
